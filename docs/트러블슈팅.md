## T-001 · 헤드리스 크롬 `--dump-dom` 이 IndexedDB 작업이 끝나기 전에 화면을 찍는다 · 2026-10-15

- 증상: Playwright 이미지의 `chrome-headless-shell --virtual-time-budget=30000 --dump-dom` 으로 `tools/browser_probe.html#selftest` 를 열면 0.7초 만에 끝나고, 결과 코드가 처음 값(`c=x g=o l=- …`) 그대로였다

- 재발 방지: 자동 점검 페이지는 끝나면 `<body data-done="1">` 을 단다(`docs/P1_설계서_Probe.md` 3.5절). 스모크는 그 표지를 기다린다
- 확인: `python3 scripts/browser_smoke.py`

## T-003 · 리다이렉트를 끈 urllib 처리기가 깨진 `Location` 에서 `ValueError` 로 멈춘다 · 2026-10-15

- 증상: 서버가 `302` 와 `Location: http://[::1`(닫히지 않은 대괄호)을 주면 `ai_probe.py` 가 `예상하지 못한 오류로 멈췄습니다: ValueError` 로 끝나고 결과 코드가 하나도 나오지 않았다(독립 점검 O-1)
- 원인: `urllib.request.HTTPRedirectHandler.http_error_302` 가 `redirect_request` 를 부르기 **전에** `urlparse(Location)` 을 한다(이 VM `/usr/lib64/python3.9/urllib/request.py` 700줄). `redirect_request` 만 `None` 으로 바꿔서는 막히지 않는다
- 조치: `_NoRedirect` 가 `http_error_301·302·303·307·308` 을 바로 `None` 으로 돌린다 → `HTTPDefaultErrorHandler` 가 `HTTPError` 로 넘겨준다. `classify_redirect` 도 읽지 못하는 `Location` 을 `o`(다른 곳)로 본다
- 재발 방지: Phase 6 의 AI 대리 호출도 같은 처리기를 쓴다(`docs/설계서_Architecture.md` 6절 '비밀'). 시험 `CrashSafetyTest`(`tests/integration/py/test_ai_probe_keyleak.py`)
- 확인: `python3 -m unittest tests.integration.py.test_ai_probe_keyleak`

## T-004 · urllib 가 `NO_PROXY` 의 CIDR·`*.도메인`·`;` 목록을 읽지 못해 평문 http 의 키가 프록시로 간다 · 2026-10-15

- 증상: `HTTP_PROXY` 와 `NO_PROXY=localhost,127.0.0.1,.corp.example,127.0.0.0/8` 이면 `127.0.0.0/8` 안의 주소도 프록시로 가서, 호출 10건이 모두 프록시를 지났고 키를 실은 호출도 프록시에 보였다(독립 점검 F-02 — 2026-10-15 다시 돌려 확인). `ALL_PROXY` 만 있으면 urllib 는 프록시를 쓰지 않는데 결과 코드는 `q=p` 였다
- 원인(이 VM 의 CPython 소스로 확인): `proxy_bypass_environment` 는 쉼표로 나눈 뒤 `.` 을 떼고 끝이 같은지만 본다 — CIDR·`*.`·`;`·빈칸 목록을 모른다(`/usr/lib64/python3.9/urllib/request.py` 2538~2546줄). 소문자 `no_proxy` 가 비어 있으면 대문자 `NO_PROXY` 를 지운다(`getproxies_environment`). `ProxyHandler` 는 `all` 키를 쓰지 않는다(800줄 — `all_open` 은 불리지 않는다). Windows `ProxyOverride` 판정(`_proxy_bypass_winreg_override`, 3.11 2631줄)은 호스트에서 포트를 떼고 `fnmatch` 로 비교해 `호스트:포트`·CIDR 항목이 맞지 않고, `<local>` 은 점 없는 이름만 맞는다 ⚠️ Windows 실기에서는 확인하지 않았다
- 조치: 키를 실을 때 평문 http 에 프록시가 걸리면 먼저 프록시 없이 닿는지 보고 직접 연결로 보낸다(`q=k`). 닿지 않으면 키를 보내지 않는다(`e=!p`). 경로 판정(`proxy_applies`)에서 `all` 을 뺐다
- 재발 방지: Phase 6 의 로컬 서버(AI 대리 호출)도 urllib 의 우회 판정을 믿지 않는다(`docs/설계서_Architecture.md` 6절 '비밀'). 시험 `KeyRouteTest`(`CaptureProxy` 가 키를 보지 못함)
- 확인: `python3 -m unittest tests.integration.py.test_ai_probe_keyleak`

## T-008 · `timeout N docker run …` 이 끊긴 뒤에도 컨테이너가 계속 돈다 · 2026-11-09

- 증상: 멈추는 정규식을 재려고 `timeout 300 docker run --rm … node …` 를 돌렸더니 명령은 끝났는데(종료 코드 143) `docker ps` 에 그 컨테이너가 남아 CPU 를 썼다
- 원인: `timeout` 은 docker 클라이언트만 끊는다. 컨테이너 안의 node 는 PID 1 이고, 처리기가 없는 PID 1 은 SIGTERM 을 받아도 죽지 않는다. 컨테이너 안에 `timeout 600 node …` 를 두어도 같다 — busybox `timeout` 은 프로그램을 자기 자리(PID 1)에서 돌리고 감시 자식이 SIGTERM 을 보내는데 무시됐다(`docker top` 에 node 하나만 남아 13분 넘게 돎, 2026-11-09)
- 조치: `docker kill <컨테이너>`
- 재발 방지: 멈출 수 있는 시험은 컨테이너 안에서 끊는다 — `markdown.test.js` '선형 시간 — 긴 글' 은 Node `spawnSync(…, {timeout})` 로 자식 프로세스(PID 1 아님)를 끊는다. 손으로 잴 때는 `docker run --init --name <이름> … timeout -s KILL <초> node …` 로 띄우고, 그래도 남으면 `docker kill <이름>`
- 확인: `docker ps --format '{{.Image}} {{.RunningFor}}'`

## T-009 · 전체 검증 17단계(렌더러 Chromium)가 2초 만에 `FileNotFoundError: … out.json` 으로 실패 · 2026-11-09

- 증상: `bash scripts/verify.sh` 의 `17 렌더러 Chromium(XSS)` 만 `실패(1) 2` — 로그는 `render_smoke.py` 가 `/tmp/ml-render-…/out.json` 을 찾지 못한 `FileNotFoundError` 하나. `docker run` 은 종료 코드 0 이었다. 바로 다시 돌린 `python3 scripts/render_smoke.py` 는 세 번 다 통과(약 8초)
- 원인: `tests/ui/cdp.js` 가 브라우저가 도중에 죽는 경우를 놓쳤다. CDP 연결이 끊기면 기다리던 요청의 약속이 영영 끝나지 않고, 남은 핸들이 없어 Node 가 out.json 을 쓰지 않은 채 종료 코드 0 으로 끝난다(CommonJS 는 끝나지 않은 약속만 남으면 0 으로 끝난다 — `node:22.23.3-alpine` 으로 확인). 재현: 실행 중 `docker exec <컨테이너> pkill -9 -f chrome-headless-shell-linux64/chrome-headless-shell` → 고치기 전 `cdp.js` 는 1초 만에 `exit=0`·out.json 없음(2026-11-09). 브라우저가 왜 죽었는지는 그때 stderr 를 남기지 않아 모른다 — ⚠️ 확인 필요(같은 VM 을 여러 계정이 쓴다. 아래 조치 뒤 다시 나면 종료 코드·신호·stderr 가 보인다)
- 조치: `cdp.js` — 연결이 끊기면 기다리던 요청을 모두 실패시키고(브라우저 종료 코드·신호·stderr 끝을 붙여), 끊긴 뒤 보내는 요청은 바로 실패, 결과를 쓰기 전에 이벤트 루프가 비면(`beforeExit`) 종료 코드 1. 같은 주입으로 `exit=1`, `CDP 연결이 끊겼다 — 브라우저 종료 코드 null · 신호 SIGKILL · stderr 끝: …`. 고친 뒤 `render_smoke.py` 15번 연속·전체 검증 18단계 통과(원래 실패는 다시 나지 않았다)
- 재발 방지: 결과 파일을 쓰는 Node 도구는 '끝나지 않는 약속' 경로를 막는다 — 외부 프로세스·소켓이 끊기면 기다리는 쪽을 실패시키고, 결과를 쓰기 전 루프가 비면 0 으로 끝내지 않는다
- 확인: `python3 scripts/render_smoke.py` → `Chromium …초: core 14개 classic script · … 실행된 XSS 0 …`, `python3 scripts/browser_smoke.py` → `스모크 통과`

## T-011 · 화면 스모크 스크린샷 단계가 단계마다 약 30초 늦거나 10분 넘게 멈춘다 · 2026-11-09

- 증상: `python3 scripts/app_smoke.py --shots docs/screenshots/P3` 가 강의 화면 390px 에서 10분 넘게 멈췄다(`docker ps` 에 컨테이너가 남음). 고친 뒤에도 스크린샷이 있는 단계마다 약 30초씩 늘었다
- 원인: 둘이었다. ① `Page.captureScreenshot` 의 `captureBeyondViewport` 가 아주 긴 화면(390px 강의 — 높이 10,074px)에서 멈췄다. ② 멈춤을 막으려고 넣은 `Promise.race([찍기, sleep(30000)])` 의 진 쪽 타이머가 일이 끝난 뒤에도 Node 이벤트 루프를 붙잡아, 프로세스가 30초 뒤에야 끝났다(단계마다 시각을 찍어 보니 CDP 일은 1.5초 안에 끝남)
- 조치: `tests/ui/cdp.js` — 창 높이를 내용 높이(최대 4,000px)로 늘린 뒤 보이는 창만 찍는다, 찍기에 30초 시한, 경주에 쓰는 기다림은 `unref` 한 타이머(`idle`). 스크린샷 두 장 단계가 32.5초 → 2.8초
- 덧붙임(같은 날): 브라우저가 끝나기를 기다리는 5초도 `unref` 로 바꿨더니, 브라우저가 먼저 끝나 `exit` 알림을 놓친 경우 루프가 비어 세 번에 한 번꼴로 `결과를 쓰기 전에 이벤트 루프가 비었다`(T-009 의 보호 문구)로 끝났다 → `waitExit` — 이미 끝났으면 바로, 아니면 끝나면 타이머를 푼다
- 재발 방지: 시한을 거는 `Promise.race` 는 진 쪽 타이머를 풀거나 `unref` 한다. 컨테이너 안 도구가 오래 돌면 `docker exec <컨테이너> ps` 로 어느 단계인지 먼저 본다(T-008 과 같이)
